ScamScope reads a suspicious message and explains the phishing warning signs. Its blind spot: it could only guess whether a link was actually dangerous.

The message under analysis
Suspicious message

URGENT: Your account has been temporarily suspended due to unusual sign-in activity. To avoid permanent closure within 24 hours, verify your identity immediately here:
http://221.15.172.85:48113/bin.sh
Failure to confirm will result in loss of access. — Security Team

⚠ BEFORE — no tool, reasoning only
Baseline agent · Amazon Nova Pro

Correctly spots urgency, account-loss threats, and a credential request. But on the actual link it can only speculate:

“The link provided does not appear to be associated with a legitimate domain…”

No verification. The model is guessing — and Bedrock's content filter even truncates the answer.

The one new tool

check_url_reputation — a URLhaus fact-checker

> agent reasons… then calls
Tool #1: check_url_reputation(url="http://221.15.172.85:48113/bin.sh")
Strands Agent
Nova Pro reasoning
→
AWS Lambda
check_url_reputation
→
Secrets Manager
URLhaus Auth-Key
→
URLhaus
threat intel (string only)

Safe by design: the tool sends only the URL string — it never opens the hostile link.

✓ AFTER — with the tool
Tooled agent · live URLhaus verdict

“The URL check result confirms that the link is malicious. URLhaus lists it as an online threat associated with malware download.”

Calibrated judgement: very likely a phishing attempt — based on both the text indicators and the confirmed malicious link.

Do not click the link. Report it, and enable MFA.

What changed

A guess became a verified fact.

  • ✓AWS Lambda hosts the tool · Secrets Manager holds the key · IAM least-privilege · CloudWatch proves real runs.
  • ✓Safe by design — the tool never fetches the hostile URL.
  • ✓Reusable pattern: drop URL reputation into any agent that reads untrusted text.
